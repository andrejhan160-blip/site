6. Пользователь — не DevOps. Все команды, которые нужно выполнить руками, оформляй как пошаговую инструкцию с точными командами и ожидаемым результатом.
7. Язык интерфейсов (бот, приложение, админка) — русский. Код, комментарии и названия — английский.
8. Приоритет: **надёжность работы из РФ > простота > фичи**. Любое решение оценивай вопросом: «переживёт ли это блокировку РКН/DPI и падение одного сервера?»
9. Не использовать сервисы, которые не работают из РФ без VPN, в цепочке, которую пользователь должен пройти БЕЗ VPN (первое подключение!). Сайт, бот, скачивание приложения и получение конфига должны быть доступны из РФ напрямую.

## 1. Цель и границы проекта

**Цель:** коммерческий VPN-сервис для пользователей из России, который:
- работает стабильно при современных методах блокировок (DPI, блокировки по IP/SNI, замедления, «белые списки»);
- продаётся через Telegram и собственное приложение;
- принимает оплату способами, доступными в РФ без зарубежных карт;
- управляется одним человеком без DevOps-опыта через админку.

**Гео:** основное — **США** (минимум 2 сервера у разных провайдеров). Дополнительно (конфигурируемо, включается позже): Нидерланды и/или Финляндия как «быстрый» сервер с низким пингом. Архитектура должна позволять добавить сервер любой страны за 15 минут (скрипт + запись в админке).

> Почему не «только США»: один сервер = единая точка отказа; один IP-диапазон = одна блокировка. Минимальная жизнеспособная конфигурация — 2×США (разные провайдеры/дата-центры) + 1×ЕС. Это и есть «3 гео» в смысле отказоустойчивости, но пользователь видит их как «США» и «Европа».

**Вне границ (не делать в MVP):** реферальная программа с выплатами, семейные тарифы, собственные DNS-фильтры рекламы, роутерные прошивки.

## 2. Архитектура (общая схема)

```
 Пользователь (РФ)
   │
   ├─ Telegram-бот ───────────┐
   ├─ Приложение (iOS/Android/│Win/macOS)   ──► API (Backend)  ──► PostgreSQL / Redis
   └─ Сайт-лендинг (Next.js)──┘                    │
                                                   ├──► Адаптеры платежей (USDT, СБП-агрегатор, Telegram Stars)
                                                   ├──► Node Manager ──► 3x-ui API на каждом сервере
                                                   ├──► Subscription endpoint (отдаёт конфиги клиенту)
                                                   └──► Monitoring / Health / Alerts (в Telegram админу)

 Серверы (ноды):  US-1 (провайдер A) | US-2 (провайдер B) | EU-1 (NL/FI)
   каждый: Xray (VLESS+Reality, VLESS+XHTTP fallback), 3x-ui панель, BBR, fail2ban, ufw
```

**Ключевой принцип:** Backend — единый «мозг». 3x-ui на нодах — только исполнитель (создать/удалить/ограничить клиента, отдать статистику). Клиенты никогда не ходят напрямую в 3x-ui.

## 3. Инфраструктура и серверы

### 3.1 Требования к нодам
- VPS: 2 vCPU, 2–4 GB RAM, 1 Gbps, трафик ≥ 5 TB/мес (или безлимит), Ubuntu 22.04/24.04 LTS.
- IPv4 обязателен. Проверять IP перед покупкой: не в списках блокировок РКН (скрипт `scripts/check-ip.sh`: проверка доступности порта 443 с пробника внутри РФ + внешние списки).
- Провайдеры для США (разные!): пример — один сервер у крупного (Vultr/DigitalOcean/Linode — их подсети чаще блокируют), второй у «незаметного» хостера с чистыми подсетями. Список кандидатов — в `docs/providers.md`, окончательный выбор за пользователем.
- Домены: минимум 3 домена в разных зонах у регистратора, работающего с РФ (для API, для подписок, для резерва). Никакой один домен не должен быть единственной точкой входа.

### 3.2 Установка ноды (автоматизация)
Сделать `infra/` с двумя вариантами:
1. **`bootstrap-node.sh`** — одна команда `curl ... | bash` на чистом Ubuntu. Делает всё из п. 3.3.
2. **Ansible playbook** `infra/ansible/` — то же самое для нескольких серверов сразу (inventory из админки).

### 3.3 Что делает bootstrap
- обновление системы, часовой пояс, swap, sysctl (BBR, tcp fastopen, увеличенные лимиты);
- ufw: открыть только 22 (потом сменить на нестандартный порт), 443, порты 3x-ui только с IP backend'а;
- fail2ban для ssh;
- ssh: только по ключу, root-логин по паролю выключен;
- установка **3x-ui** (последняя стабильная версия), генерация логина/пароля/пути панели, привязка панели к localhost + доступ через SSH-туннель или WireGuard-канал с backend;
- настройка Xray inbound'ов (раздел 4);
- регистрация ноды в backend (`POST /internal/nodes/register` с одноразовым токеном);
- установка node-exporter + healthcheck-агента;
- автообновление безопасности (unattended-upgrades), автоперезапуск xray при падении (systemd `Restart=always`).

## 4. Протоколы и обход блокировок

### 4.1 Основной: VLESS + Reality (TCP, порт 443)
- `flow: xtls-rprx-vision`.
- Reality `dest`/`serverNames`: подбирать **реальный крупный сайт с TLS 1.3 и HTTP/2, не заблокированный в РФ, географически близкий к серверу** (для США — например, крупные CDN-домены). Список кандидатов и скрипт проверки `scripts/find-reality-sni.sh` (проверяет TLS1.3, h2, отсутствие редиректа, пинг).
- Отдельная пара ключей и `shortIds` на каждую ноду.
- **Один клиент = один UUID на всех нодах** (синхронизация через backend), чтобы пользователю не нужно было ничего менять при переключении сервера.

### 4.2 Резерв 1: VLESS + XHTTP (за CDN) 
- Inbound VLESS через XHTTP, доступный через Cloudflare-совместимый CDN по отдельному домену. Работает, когда IP сервера заблокирован напрямую.
- Использовать только как fallback (медленнее). Клиентское приложение переключается на него автоматически (раздел 8.4).

### 4.3 Резерв 2 (опционально, вкл. флагом): Hysteria2 или Shadowsocks-2022
- Для мобильных сетей, где TCP режут агрессивно. Включать по решению пользователя, реализовать в конфиге как отключённый inbound.

### 4.4 Что НЕ использовать как основной протокол
- WireGuard/OpenVPN «как есть» — детектируются DPI. Если очень нужно — только AmneziaWG и только как опция.

### 4.5 Маршрутизация (на стороне клиента)
- Российские сайты (`geosite:category-ru`, `geoip:ru`, банки, Госуслуги, Яндекс, VK, Ozon, WB, СБП-приложения) — **напрямую**, минуя VPN. Это критично: без этого пользователи будут жаловаться, что «не работает банк».
- Всё остальное — через VPN.
- Режим «Глобальный» (всё через VPN) — переключатель в приложении.
- Правила маршрутизации доставляются с сервера в составе подписки и обновляются без обновления приложения.

## 5. Backend (API)

### 5.1 Стек
- **Node.js 20 + TypeScript + NestJS** (или Fastify), PostgreSQL 16, Redis, Prisma.
- Docker Compose для локальной разработки и для продакшна (один VPS «control-plane», НЕ на одной машине с VPN-нодами).
- Обязательно: OpenAPI-спецификация автогенерируется и лежит в `docs/openapi.json`.

### 5.2 Доменная модель
- `User` — id, telegramId (nullable), email (nullable), createdAt, status, lang, refCode.
- `Plan` — название, длительность (дни), лимит трафика (GB или безлимит), лимит устройств, цена в RUB / USDT / Stars.
- `Subscription` — user, plan, startsAt, expiresAt, trafficLimit, trafficUsed, deviceLimit, status (trial/active/expired/blocked).
- `Device` — user, platform, appVersion, lastSeenAt, subscriptionToken.
- `Node` — name, country, provider, ip, domain(ы), protocolы, 3x-ui credentials (шифрованно), status, load, weight, isPublic.
- `NodeClient` — связь user↔node, uuid, inboundId, sync status.
- `Payment` — user, provider (crypto/sbp/stars), amount, currency, status, externalId, rawWebhook.
- `Event` / `AuditLog`.

### 5.3 Ключевые модули
1. **Auth**: вход через Telegram (Login Widget / initData из Mini App / одноразовый код от бота) и через email + 6-значный код. JWT + refresh. Никаких паролей в MVP.
2. **Subscription endpoint**: `GET /sub/{token}` — отдаёт список конфигов в форматах: base64 (v2ray), sing-box JSON, clash. Заголовки `subscription-userinfo` (трафик/срок), `profile-update-interval`. Токен — 32+ символа, ротируется по запросу пользователя. Доступен по **нескольким доменам** (список в env), приложение хранит все.
3. **Node Manager**: адаптер к API 3x-ui (`login`, `addClient`, `updateClient`, `delClient`, `getClientTraffics`, `onlines`). Очередь задач (BullMQ): создание клиента на всех активных нодах, блокировка по истечении/перерасходу, пересинхронизация при добавлении ноды, ночная сверка «что в БД vs что на ноде».
4. **Payments**: единый интерфейс `PaymentProvider { createInvoice, handleWebhook, verifySignature }` и три реализации (раздел 6). Идемпотентность вебхуков по `externalId`.
5. **Billing**: активация/продление подписки, пробный период (например, 3 дня, 1 устройство), напоминания за 3 дня и за 1 день до окончания, авто-блокировка.
6. **Health & Monitoring**: каждые 60 сек — проверка нод (TCP 443, Xray API, нагрузка, свободный трафик). Результаты влияют на `weight` ноды и порядок серверов в подписке. Алерты в Telegram админу (нода недоступна > 3 мин, трафик > 80% лимита, ошибка платёжки).
7. **Probes из РФ**: отдельный лёгкий агент (`probe/`), который можно запустить на любой машине/дешёвом VPS внутри РФ или на домашнем ПК: проверяет, доступны ли ноды, домены подписки и API из России, и шлёт результат в backend. Это главный источник правды о «работает ли у пользователей».
8. **Admin API**: CRUD планов, нод, пользователей; продление вручную; выдача промокодов; статистика (MRR, активные, churn, трафик по нодам).
9. **Notifications**: через бота (Telegram) и email (SMTP-провайдер, доступный из РФ).

### 5.4 Нефункциональные требования
- Логи без содержимого трафика. Хранить только: факт подключения, объём, нода. Настраиваемый срок хранения (по умолчанию 30 дней).
- Rate limiting на публичных эндпоинтах, защита вебхуков подписью и IP-allowlist.
- Бэкапы PostgreSQL ежедневно в S3-совместимое хранилище (два разных провайдера), проверка восстановления раз в неделю скриптом.
- Всё поднимается одной командой `make deploy` на новом control-plane сервере (disaster recovery ≤ 1 час).

## 6. Оплата

### 6.1 Криптовалюта (USDT TRC-20 / TON)
- Провайдер: **Cryptomus** или **CryptoBot (@CryptoBot API)** — реализовать оба под общим интерфейсом, включать через env. Вебхуки с проверкой подписи. Пересчёт RUB→USDT по курсу провайдера на момент инвойса.

### 6.2 СБП через агрегатор
- Реализовать адаптер под API агрегатора, который пользователь выберет (`TODO_USER: название агрегатора и ключи`). Сделать абстракцию так, чтобы замена агрегатора = один файл. Обязательно: создание счёта → ссылка/QR → вебхук → проверка статуса запросом (на случай потери вебхука).

### 6.3 Telegram Stars
- Через `sendInvoice` с `currency: XTR` в боте. Обработка `pre_checkout_query` и `successful_payment`. Отдельные цены в Stars в модели плана.

### 6.4 Общее
- Промокоды (скидка % / дни в подарок), одноразовые и многоразовые.
- Чек/квитанция пользователю в боте. Возвраты — вручную через админку с пометкой.
- Все суммы хранить в минорных единицах (копейки/центы), никаких float.

## 7. Telegram-бот

Стек: **grammY** (TypeScript) внутри того же монорепо, webhook-режим.

Функции:
- `/start` (с deep-link ref/промо) → регистрация → 3-дневный триал автоматически.
- Главное меню: «Подключиться» (ссылки на приложение под платформу + кнопка «Открыть в приложении» через deep-link `myvpn://import?url=...`), «Купить/Продлить», «Мои устройства», «Серверы и статус», «Помощь».
- Покупка: выбор плана → способ оплаты → счёт → после оплаты сообщение с подтверждением.
- «Не работает?»: пошаговая самодиагностика (обновить подписку, сменить сервер, включить резервный режим) + кнопка «Написать в поддержку» (пересылка админу с контекстом: id, нода, версия приложения, ОС).
- Статус серверов в реальном времени из health-модуля.
- Админские команды (только для `ADMIN_TG_IDS`): `/stats`, `/node`, `/user <id>`, `/extend <id> <days>`, `/broadcast`.
- Telegram Mini App (опционально, фаза 6): личный кабинет внутри Telegram.

## 8. Собственное приложение (клиент)

### 8.1 Решение
- **Flutter** (iOS, Android, macOS, Windows) + ядро **sing-box** через нативный мост.  
  База: изучить и переиспользовать подход open-source проекта Hiddify (Flutter + `libcore` на Go через FFI/Platform Channels). Лицензию соблюсти (указать в `LICENSES.md`).
- Причина: sing-box поддерживает VLESS+Reality, XHTTP, Hysteria2, правила маршрутизации; одна кодовая база на 4 платформы.
- Платформенные требования, о которых **обязательно** предупредить пользователя в `docs/app-store-notes.md`: iOS требует Apple Developer ($99/год) и Network Extension; Apple удаляет VPN-приложения из российского App Store по требованию РКН — планировать распространение через TestFlight/зарубежный аккаунт; Android — APK с сайта/бота + Google Play как дополнение; Windows/macOS — установщики с сайта, подпись кода.

### 8.2 Экраны (MVP)
1. Онбординг: вход через Telegram (открыть бота, получить код) или email-код.
2. Главный: большая кнопка «Подключить», текущий сервер, статус, скорость, трафик/срок.
3. Серверы: список из подписки, авто-выбор (лучший пинг), ручной выбор, флаги стран.
4. Настройки: режим маршрутизации («Умный» — РФ напрямую / «Всё через VPN»), автозапуск, kill-switch (где поддерживается), протокол (авто/основной/резервный), язык.
5. Подписка: план, срок, кнопка «Продлить» (открывает бота/сайт).
6. Помощь: диагностика (тест подключения к каждой ноде, экспорт логов), ссылка на поддержку.

### 8.3 Технические требования
- Подписка обновляется: при запуске, каждые 6 часов, по pull-to-refresh. Хранить **несколько URL подписки** и перебирать их при недоступности.
- Конфиг sing-box генерируется на клиенте из подписки + локальных настроек.
- Обновления приложения: проверка версии через API (`/app/version`) + ссылки на скачивание из РФ.
- Crash-репорты и аналитика — только self-hosted (например, свой эндпоинт), без Firebase/Sentry cloud (могут не работать из РФ).

### 8.4 Авто-восстановление соединения
Алгоритм при отсутствии интернета через VPN > 15 сек:
1. Переключиться на другую ноду того же гео → 2. на другой протокол (XHTTP fallback) → 3. на другой гео → 4. обновить подписку с резервного домена и повторить. Все переключения логируются и отправляются в backend как телеметрия (без содержимого трафика).

## 9. Сайт и админка

- **Лендинг** (Next.js, статика, хостинг в РФ или через CDN доступный из РФ): что это, цены, скачать приложение, кнопка в бота. Без прямой рекламы обхода блокировок в тексте (см. раздел 11).
- **Админка** (Next.js + shadcn/ui, тот же монорепо): дашборд (MRR, активные подписки, онлайн по нодам, статус нод и пробников из РФ), пользователи (поиск, продление, блокировка, история платежей), ноды (добавить через мастер: вставил IP + ssh-ключ → нажал «Установить» → бэкенд прогоняет bootstrap), планы и промокоды, рассылки, логи алертов. Доступ: только через Telegram-логин админа + 2FA (TOTP).

## 10. Надёжность и «работа без перебоев»

Обязательные меры (реализовать все):
1. ≥2 ноды в основном гео у разных провайдеров; подписка всегда содержит все живые ноды.
2. Автоматическая деактивация ноды из подписок при падении health-check и возврат после восстановления.
3. Ротация: скрипт `scripts/rotate-node.sh` — поднять новую ноду, перенести клиентов, вывести старую (при блокировке IP). Целевое время — 20 минут, в основном ожидание VPS.
4. Несколько доменов для API/подписок; DNS у двух провайдеров; TTL 300.
5. Пробники из РФ (раздел 5.3 п.7) как источник алертов: «недоступно из РФ» важнее «недоступно из-за рубежа».
6. Мониторинг: Prometheus + Grafana + Uptime Kuma на control-plane; алерты в Telegram.
7. Бэкапы БД и конфигов Xray/3x-ui (ежедневно, 2 хранилища).
8. Runbook `docs/runbook.md`: что делать при каждом типе инцидента (нода упала, IP заблокирован, домен заблокирован, платёжка не шлёт вебхуки, БД упала), с точными командами.
9. Нагрузочный тест: 500 одновременных клиентов на ноду (симуляция) — документировать результат.

## 11. Безопасность, приватность, юридические заметки

- Не хранить содержимое трафика и DNS-запросы. Политика конфиденциальности — сгенерировать `docs/privacy.md`.
- Все панели 3x-ui недоступны из интернета напрямую.
- Секреты — в env / секрет-менеджере, ротация ключей Reality при компрометации — одной командой.
- **Юридическая заметка для пользователя (Claude Code должен вывести её в `docs/legal-ru.md`, не давать юридических советов):** в РФ действуют ограничения на рекламу средств обхода блокировок и требования к VPN-сервисам; регистрация юрлица, налоги, формулировки на сайте/в боте и приём платежей — вопрос к юристу. В продукте избегать формулировок «обход блокировок» в публичных материалах; использовать «защита соединения», «приватность», «доступ к рабочим сервисам».

## 12. Фазы работ и критерии готовности (DoD)

| Фаза | Что делаем | DoD |
|---|---|---|
| **0. Скелет** | Монорепо (pnpm workspaces): `apps/api`, `apps/bot`, `apps/admin`, `apps/landing`, `apps/mobile`, `packages/shared`, `infra/`, `docs/`. Docker Compose, CI (lint+test), `.env.example`, `CLAUDE.md`. | `docker compose up` поднимает API+БД+Redis; `pnpm test` зелёный |
| **1. Ноды** | `bootstrap-node.sh`, Ansible, конфиги Xray (Reality + XHTTP), `find-reality-sni.sh`, `check-ip.sh`, hardening. | На чистом VPS одной командой поднимается нода; подключение клиентом Hiddify/v2rayNG работает; панель недоступна извне |
| **2. Backend ядро** | Модель данных, auth, Node Manager (адаптер 3x-ui), subscription endpoint, health-checks, admin API, OpenAPI. | Создание пользователя → UUID появляется на всех нодах ≤ 10 сек; `/sub/{token}` импортируется в Hiddify; падение ноды убирает её из подписки |
| **3. Оплата + бот** | Три провайдера оплаты, биллинг, триал, промокоды, бот полностью. | Тестовая оплата каждым способом активирует подписку; напоминания приходят; вебхуки идемпотентны |
| **4. Приложение** | Flutter-клиент с sing-box, экраны MVP, авто-восстановление, обновление подписки, «умная» маршрутизация. | Работает на Android + macOS (первые), затем Windows, iOS; переключение нод без переустановки; банк-приложение РФ работает при включённом VPN |
| **5. Админка + лендинг** | Дашборд, управление, мастер добавления ноды, лендинг. | Добавление ноды из админки без SSH руками; лендинг открывается из РФ |
| **6. Надёжность** | Пробники из РФ, мониторинг, алерты, бэкапы, ротация, runbook, нагрузочный тест. | Симуляция падения ноды и блокировки домена проходит по runbook без потери клиентов |
| **7. Полировка** | Mini App, i18n, автообновления приложения, документация пользователя. | Полный «путь клиента» от `/start` до подключённого VPN проходит за ≤ 3 минуты |

Тесты: unit (биллинг, адаптеры платежей, генерация подписки), интеграционные (3x-ui адаптер против тестовой ноды в Docker), e2e для бота (моки Telegram API).
