# Visa la Vida — лендинги ВНЖ Испании

Статический сайт: три посадочных страницы под разные сегменты трафика,
страница благодарности и политика обработки персональных данных.
Ни фреймворков, ни рантайма — обычные HTML, CSS и один JS-файл.

## Что здесь лежит

| Путь | Что это |
| --- | --- |
| `site.config.json` | **Все настройки.** Домен, контакты, пиксель, приём заявок. Единственный файл, который нужно править перед запуском. |
| `build.js` | Генератор. Собирает все страницы из данных и шаблонов. Без зависимостей. |
| `src/styles.css` | Стили. Встраиваются в каждую страницу при сборке. |
| `src/app.js` | Логика страницы: модалка, валидация, отправка заявки, события пикселя, баннер согласия. |
| `assets/` | Картинки и шрифты. Готовые файлы, ничего собирать не надо. |
| `tools/make-og.py` | Перерисовывает картинки для превью в соцсетях (нужен `pillow`). |
| `index.html`, `spain-*/`, `thank-you/`, `privacy/`, `404.html` | **Результат сборки.** Их и нужно заливать на хостинг. |

Чтобы поменять, какой сегмент показывается на корне, в `build.js` в
функции `main()` замените `SEGMENTS.visa` на `SEGMENTS.business` или
`SEGMENTS.residence` и пересоберите.

## Сборка

```bash
node build.js
```

Пишет все страницы, `assets/site.js`, `robots.txt` и `sitemap.xml`.
В конце печатает список того, что ещё не настроено — только в консоли,
на самих страницах ничего лишнего не появляется.

## Деплой

Залейте на хостинг **содержимое этой папки** — так, чтобы `index.html`
оказался в корне домена. Структура адресов:

```
/                     основной лендинг (тот же, что /spain-visa/)
/spain-visa/          лендинг «есть виза, устали продлевать»
/spain-business/      лендинг «есть бизнес»
/spain-residence/     лендинг «заканчивается ВНЖ в Европе»
/thank-you/           страница после заявки (noindex)
/privacy/             политика обработки персональных данных
```

Корень отдаёт основной лендинг, чтобы по голому домену открывалось
предложение, а не страница выбора. Он же и `/spain-visa/` — одна и та
же страница, поэтому корень указывает `canonical` на `/spain-visa/`:
в индексе остаётся один адрес, и это именно тот, который стоит в
объявлениях. В `sitemap.xml` корень не попадает по той же причине.

Папки `src/` и `tools/` и файл `build.js` на хостинг заливать не нужно —
они нужны только для пересборки.

Хостинг должен уметь отдавать `index.html` для адреса с косой чертой на
конце (это умеет любой: nginx, Apache, Netlify, Vercel, GitHub Pages,
Cloudflare Pages, Timeweb, Beget).

## Чек-лист перед запуском рекламы

Пункты 1–3 обязательны. Без них деньги за клики будут списываться,
а заявки — теряться.

### 1. Указать домен

В `site.config.json` заменить `origin` на реальный адрес:

```json
"origin": "https://ваш-домен.ru"
```

От этого зависят `canonical`, `sitemap.xml` и **абсолютные ссылки на
og:image** — без них Facebook и Telegram не покажут картинку при
репосте ссылки. Пересобрать: `node build.js`.

### 2. Настроить приём заявок и **проверить его**

Есть два канала, можно включить оба — заявка уйдёт в каждый.

**Вариант А (надёжный) — свой вебхук.** В `integrations.leadEndpoint`
укажите URL, который принимает `POST` с JSON. Подойдёт сценарий в
Make / Zapier / n8n или свой скрипт. Требования: отвечать кодом `2xx`
и отдавать заголовок `Access-Control-Allow-Origin` с вашим доменом.

Форма JSON:

```json
{
  "name": "Иван", "phone": "+34600123456", "segment": "visa",
  "page_url": "https://…/spain-visa/?utm_source=fb",
  "utm_source": "fb", "utm_medium": "", "utm_campaign": "…",
  "utm_content": "", "utm_term": "", "fbclid": "…",
  "referrer": "…", "created_at": "2026-09-07T12:00:00.000Z",
  "event_id": "lead.mtracfm4.oardk51b"
}
```

**Вариант Б (без сервера) — formsubmit.co.** Уже включён и настроен на
`evgeniqstart@gmail.com`. **Требует однократной активации:** после
первой заливки на хостинг отправьте заявку сами, откройте письмо от
formsubmit.co и нажмите ссылку подтверждения. **Пока это не сделано,
formsubmit принимает заявки и никуда их не отправляет.**

> Проверьте канал реальной заявкой до включения рекламы. Если ни один
> канал не ответил успехом, посетитель увидит сообщение об ошибке со
> ссылками на WhatsApp и Telegram, а событие `Lead` в Meta **не**
> отправится — так вы не увидите в отчётах конверсий, которых не было.

### 3. Подтвердить домен в Meta

Events Manager → Настройки → Проверка домена → способ «Мета-тег».
Скопировать значение `content` в `integrations.metaDomainVerification`
и пересобрать. Без этого не работает Aggregated Event Measurement, а
значит теряется часть конверсий с iOS.

### 4. Проверить пиксель

Пиксель `2302371210508014` уже стоит на всех страницах. Установите
расширение Meta Pixel Helper и пройдите путь целиком. Ожидаемая
последовательность:

| Событие | Когда | Тип |
| --- | --- | --- |
| `PageView` | загрузка страницы | стандартное |
| `ViewContent` | открытие формы | стандартное |
| `Lead` | **успешная** отправка заявки | стандартное, с `eventID` |
| `Contact` | клик по Telegram/WhatsApp на `/thank-you/` | стандартное |
| `LeadFormOpen`, `LeadFormStart`, `LeadSubmitFailed`, `ThankYouView`, `VideoPlay` | детали воронки | кастомные |

`Lead` отправляется **ровно один раз** и всегда с `eventID` — если
позже подключите Conversions API, Meta сама склеит браузерное и
серверное событие и не посчитает конверсию дважды.

Кампанию оптимизируйте на `Lead`. Пока объём заявок мал, для обучения
подойдёт `ViewContent`.

### 5. Согласие на cookie (для трафика из ЕС)

По умолчанию `integrations.consentMode: "eu"`: пиксель загружается с
`consent revoke` и **не отправляет ни одного события**, пока посетитель
не нажмёт «Принять». Отложенный `PageView` уходит сразу после согласия,
так что данные не теряются.

Если весь трафик заведомо вне ЕС и Великобритании — поставьте `"off"`,
баннер исчезнет и пиксель заработает с первого кадра. Для Испании и ЕС
оставляйте `"eu"`: реклама с пикселем без согласия нарушает GDPR.

### 6. Заполнить реквизиты в политике

В `legal.operator` указать юридическое название и адрес компании вместо
`Visa la Vida`. Модерация Meta и посетители из ЕС проверяют эту
страницу; шаблонная политика без реквизитов — частая причина отказа.

### 7. Conversions API (по желанию, но заметно повышает качество)

`integrations.capiWebhook` — URL вашего релея. Страница отправит туда
готовый payload: телефон и имя уже хешированы SHA-256, `event_id`
совпадает с браузерным. Релею остаётся добавить access token и
переслать на `graph.facebook.com/v21.0/<pixel_id>/events`.

## UTM-метки

Ссылки в объявлениях можно размечать как обычно:

```
https://ваш-домен.ru/spain-visa/?utm_source=facebook&utm_medium=cpc&utm_campaign=visa_ru_01&utm_content=video_a
```

`utm_*`, `fbclid` и `gclid` сохраняются на всю сессию, доезжают до
`/thank-you/`, попадают в заявку и в текст сообщения в мессенджер —
видно, какое объявление привело обращение.

## Замена картинок

**Фото в первый экран.** Сейчас стоят три фото:

| Файл | Лендинг | Сюжет |
| --- | --- | --- |
| `assets/hero-visa.jpg` | `/spain-visa/` и корень | терраса, вид на побережье |
| `assets/hero-business.jpg` | `/spain-business/` | рабочее место, светлый интерьер |
| `assets/hero-residence.jpg` | `/spain-residence/` | жилой район на закате |

Рядом лежат `.webp` того же имени — их браузер и берёт, `.jpg` остаётся
запасным. Чтобы заменить фото, положите новые файлы с теми же именами
(оба формата) и пересоберите. Если нужен один снимок на все три
лендинга — назовите его `assets/hero.jpg`, он подхватится там, где нет
файла под конкретный сегмент.

Готовьте кадр **4:5, шириной от 1120 px**: рамка обрезает по этим
пропорциям, а низ растворяется под подпись, так что лицо должно быть в
верхней трети. Если снимок другого формата, кадрирование можно сдвинуть
полем `heroPosition` у сегмента в `build.js`.

Если фото убрать совсем, первый экран вернётся к карточке ВНЖ —
ничего не ломается.

**Картинки для соцсетей.** `python3 tools/make-og.py` (нужен
`pip install pillow`) перерисует `assets/og-*.jpg` — 1200×630, как
просят Meta и Telegram. Тексты задаются в начале скрипта.

## Что было исправлено при переносе

Исходник приехал как один HTML на 3.3 МБ: 16 ассетов в base64,
распаковка через `DecompressionStream`, затем React и дизайн-рантайм, и
только потом хоть какая-то разметка. Что с этим было не так и что
сделано:

- **Пустая страница для краулеров.** Meta при проверке ссылки JS не
  выполняет — видела только `<title>Bundled Page</title>`. Теперь текст
  и og-теги лежат в исходном HTML.
- **Битые картинки.** Шаблон подставлял `assets/hero-*.jpg` и
  `assets/logo-*.png`, которых в архиве не было — на каждом лендинге
  ломались логотип и первый экран. Ассеты извлечены, логотип
  перекрашен под тёмные темы, первый экран собран из реального файла.
- **Вес.** Первый экран: 181 КБ вместо 3.3 МБ. Картинка ВНЖ ужата с
  2 МБ PNG до 123 КБ WebP, шрифты подключены напрямую вместо Google
  Fonts.
- **Потеря заявок.** Отправка шла с `.catch(() => {})`, и посетителя
  вели на «спасибо» независимо от результата. Теперь неуспех виден и
  посетителю, и в консоли, с запасным выходом в мессенджер.
- **Двойной `Lead`.** При включённом CAPI событие отправлялось дважды —
  с `eventID` и без. Теперь ровно одно, всегда с `eventID`.
- **PII в открытом виде.** В вебхук CAPI уходили незахешированные имя и
  телефон. Теперь SHA-256 в браузере.
- **`ipapi.co` на каждой загрузке.** Сторонний запрос с лимитом ~1000 в
  сутки — под рекламным трафиком отваливается, плюс IP посетителя
  уезжает третьей стороне до согласия. Заменено на определение кода
  страны по часовому поясу, без запросов.
- **Отладочный переключатель** «Preview / Visa / Business / Residence»
  показывался всем, кто открывал сайт по http. Удалён.
- **Нет политики и согласия.** Добавлены страница политики, рабочие
  ссылки на неё и баннер согласия, управляющий пикселем.
- **Адреса.** `/thank-you/` стал настоящим URL (годится как цель
  конверсии) вместо `#/thank-you`; добавлены canonical, sitemap,
  robots, 404 и фавиконки.
